# 아바타 연구 글 게시 기록

작업일: 2026-10-18, Asia/Seoul.

## 요청과 반영 범위

사용자는 지금까지의 VTuber 아바타 제작, 성과와 한계, 돌파 방향, 기술적 제약과 궁극적 목표를 기존 Live2D 기반 아바타와 비교하는 상세 Markdown 글을 블로그에 작성하도록 요청했다.

- 정식 글: [`_research/vtuber-avatar-live2d-gap.md`](../_research/vtuber-avatar-live2d-gap.md).
- 공개 주소: [한 장의 일러스트로 버튜버 아바타 만들기: Live2D와의 간극](https://cbh456746.github.io/research/vtuber-avatar-live2d-gap/).
- Research에 심층 연구 기록으로 배치하고 기존 프로젝트 소개 세 곳에서 연결했다. Projects나 Play에 같은 본문을 복제하지 않았다.
- Archive에 VTuber와 Live2D 태그를 추가했다. 기존 분류와 글 주소는 보존했다.
- 12개 본문 절, 목차, 10개 비교·절차 표를 작성했다. 현재 구현, 과거 검증 결과, 후속 제안을 구분했다.
- Home, Resume, RSS 정책, 추적 설정, 프로젝트 소스·실행파일은 변경하지 않았다.

## 근거와 공개 검수

블로그 운영 인수인계서, 기존 프로젝트 소개, 이미지 전환형 앱의 README·검증·아트 문서와 프레임 선택 코드를 대조했다. Mesh 실험은 10월 9일·15일의 제작 기록과 방향별 형태 제작 문서를 검토했다. 공식 Cubism 소재 분리·파라미터·얼굴 XY·클리핑·물리·3D 회전 보조 문서와 VTube Studio API를 본문에 연결했다.

비공개 개발 기록은 기술적 결과와 한계를 설명하는 근거로만 사용했다. 원본 그림, 파츠, 생성 중간물, 실패 렌더, 인증 자료, 개인 경로, 원시 대화·로그는 추가하지 않았다. 새 글에는 새 이미지나 영상 파일을 포함하지 않는다.

추가된 행을 대상으로 개인 경로·연락처·비밀값·로컬 주소·비공개 에셋 식별 패턴을 검사해 발견 0건을 확인했다. 본문을 읽으며 민감 정보, 검증되지 않은 성과와 공개 범위를 재검토했다. 패턴 검사가 모든 정보 노출 가능성을 증명하는 것은 아니다.

## 게시와 확인 결과

시작 커밋은 `f069a652874262c18058361edf189ad438930066`이었다. 원격 main과 일치하고 작업 트리가 깨끗한 상태에서 시작했다. 작성자 설정은 승인된 공개 이름과 GitHub noreply 형식을 확인했다. 일반 푸시를 사용했으며 이력 재작성은 하지 않았다.

본문 게시 커밋: [`5f48fb4809ed3c47074e3dcc90e68294d75f1311`](https://github.com/cbh456746/cbh456746.github.io/commit/5f48fb4809ed3c47074e3dcc90e68294d75f1311).

해당 커밋의 [GitHub Pages 실행](https://github.com/cbh456746/cbh456746.github.io/actions/runs/39114084220)은 build와 deploy 모두 성공했다.

| 검사 | 확인 결과 |
| --- | --- |
| `npm run validate` | 통과 |
| `git diff --cached --check` | 통과. 최초 발견한 Markdown 줄 끝 공백 수정 후 확인 |
| 목차와 내부 링크 | 12개 본문 앵커와 관련 프로젝트 대상 확인 |
| 공개 본문 | HTTP 200, 제목·마지막 절·13개 H2·10개 표 확인 |
| Research·Archive | 새 글 링크 확인 |
| 관련 프로젝트 세 곳 | 새 연구 글 링크 확인 |
| `search.json` | 유효한 JSON, 새 글 1개, research 분류 확인 |
| `feed.xml` | 유효한 RSS XML, 새 글 1개 확인. RSS 사양은 유지 |
| 브라우저 | 공개 본문·목차·표 표시, 목차를 통한 `#pipeline` 이동 확인 |

로컬에 Ruby/Bundler 실행 환경이 없어 로컬 Jekyll 빌드는 실행하지 않았다. 실제 Jekyll 빌드와 생성 RSS 검사는 위 Actions 결과로 확인했다. 실제 모바일 기기의 별도 실기 검사는 수행하지 않았다.

공개 화면 검수에서 목차 이동 시 제목 일부가 고정 메뉴에 가려지는 것을 발견했다. 후속 변경은 새 글의 명시적 앵커에 `article-anchor` 클래스를 붙이고, 해당 클래스에만 `scroll-margin-top`을 적용한다. 기존 레이아웃 전체를 재설계하지 않는다.

## 이후 유지보수

새 모델 실험이 완료되면 글의 기준일·현재 판정·해당 절의 근거를 함께 갱신한다. 9방향 기준, 중간 자세 검증, 표정·물리 결합, 실제 방송 검증은 현재 연구 계획과 구분해 결과를 추가한다. 글을 게시했다는 이유로 모델의 개발 상태를 완료로 바꾸지 않는다.

목차 구조를 바꾸면 앵커와 표를 다시 확인한다. 일반 글 수정에서는 소스 검사 후 해당 커밋의 Pages 결과와 실제 본문을 확인하며, 관련 없는 모델 테스트나 이력 교체를 반복하지 않는다.
