# 1,000편 이상을 위한 참조 기능 규모·실패 점검

기준: 2026-10-30. 사용자가 구현 도중 1,000편 이상에서의 작동과 이전 실패의 재점검을 요청했다. 운영 정본은 [AI_REFERENCE_GUIDE.md](AI_REFERENCE_GUIDE.md), 배포 증거는 [AI_REFERENCE_PUBLICATION.md](AI_REFERENCE_PUBLICATION.md)에 남긴다.

## 발견한 구조 문제와 보완

처음 구현은 현재19편의 전체 요약을 index.json 한 파일에 담았다. 소규모 탐색에는 가능하지만 글 수에 따라 에이전트가 처음 읽어야 할 자료도 커진다. 이를 1,000편 이상에서 그대로 권장하는 것은 적합하지 않다.

schema v2는 다음과 같이 바꿨다.

- 시작 색인은 전체 글/태그가 아니라 분류5개와 태그 디렉터리의 진입점만 제공한다.
- 글별 카탈로그는 최대25항목, 모든 JSON 페이지는64KiB 이하로 제한한다. 태그 목록 자체도 최대100항목씩 나눈다.
- `context/search.py`는 선택한 카탈로그의 메타데이터를 로컬 검색하고 기본5개·최대20개 결과만 반환한다. 에이전트에 전체 본문/색인을 붙이지 않는다.
- 원문·프롬프트·미디어는 선택 후 읽는다. 전체 내보내기는 요청받은 경우에만 사용한다.
- 시작 색인과 페이지의 source_commit이 다르면 검색을 중단한다. 삭제/축소 후 오래된 생성 Markdown·카탈로그 JSON을 정리한다.
- 전체 본문 묶음의 문자열 반복 결합을 부분 목록+join으로 바꿔 불필요한 재복사를 줄였다.

## 로컬 대규모 시험 결과

`scripts/test_context_export.py`의 합성 fixture는 **1,205편, 1,206태그**를 생성한다. 글은 네 종류에 분산하고 약8KB의 설명과 개별 코드 payload를 넣었다. 태그 수까지 증가시키기 위해 공통 태그1개와 글별 태그를 사용했다.

이 환경의 한 번 실행에서:

| 측정/검사 | 결과 |
| --- | --- |
| 생성된 글/고유 ID | 1,205개, 누락·중복 없음 |
| 시작 색인 | 1,535바이트, 글 전체 배열 없음 |
| 가장 큰 JSON 카탈로그 페이지 | 31,280바이트,64KiB 이하 |
| 카탈로그·태그 JSON 페이지 | 1,368개 |
| 페이지 항목 제한 | 글25개/태그100개 이하 |
| 마지막 태그·글 조회 | Topic-1204 → unique-1204 일치1개 |
| 데이터 축소 후 정리 | 옛 두 번째 페이지와 제거된 본문 파일 삭제 확인 |
| 내보내기 소요 | 약10.238초, 로컬 합성 시험의 단일 측정 |
| 전체 단위 검사 | 17개 통과, 약18.076초 |

특정 크기의 메타데이터·합성 본문을 사용한 한 번의 로컬 측정이다. 실제1,205편·대용량 이미지/영상·동시 접속·네트워크·모델 답변 품질의 부하 시험이 아니다. 속도 보장이나 토큰 절감률로 해석하지 않는다. 개별 요약이 페이지 예산보다 크면 조용히 자르지 않고 명시적으로 실패시킨다.

## 실제 Jekyll 경로의 규모 검사

CI는 공개 소스와 분리된 `_context_scale_source`에 합성1,205편과 비공개·미래·초안 제외 대상을 만든다. 실제 Jekyll action으로 렌더한 뒤 동일 exporter에서 수·중복·제외·페이지 크기·SHA·코드·프롬프트27개를 확인한다. 테스트 결과는 `_context_scale_site`이며 실제 Pages 업로드 대상 `_site`와 다르다. 두 경로는 빌드와 Git에서 명시적으로 제외한다.

이 경로는 로컬에 Ruby가 없어 GitHub Actions에서 검증한다. 해당 실행의 성공은 게시 기록에서 확인한다. 최소 레이아웃을 쓰는 합성 테스트로, 전체 기존 테마와 실제 미디어1,205편의 성능 시험을 대신하지 않는다. 실제19편은 별도 본 사이트 빌드와 공개 응답으로 확인한다.

수정 커밋 `924a496325b9562761707d53b101d26da76771a0`의 [Actions 41020600569](https://github.com/cbh456746/cbh456746.github.io/actions/runs/41020600569)에서 전체 단계가 성공했다. 실제 Jekyll fixture는1,205편·카탈로그49페이지·프롬프트27개·비공개/미래/초안 제외를 확인했고 시작 색인은1,523바이트였다. 같은 실행의 본 사이트19편 생성과 Pages 배포도 성공했다. CI의 합성 내보내기/검사 시간은 약3.717초이며 전체 사이트 성능 보장이 아니다.

## 남는 운영 조건

요약·태그·관련 글을 원문과 맞게 유지해야 한다. 단어 일치 검색은 의미 검색이나 본문 전체 검색이 아니므로 관련 글 누락을 일반적으로 없앴다고 주장하지 않는다. 문장 대신 핵심 용어를 고르고 필요하면 다른 분류·태그와 원문을 확인한다. 버전 혼합·접근 오류는 알리고 재시작한다. 공개 파일 수와 전송량은 자료 수에 따라 증가하므로 더 큰 규모/대용량 미디어는 별도 측정한다.
