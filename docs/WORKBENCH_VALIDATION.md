2026-11-02, M-13. 로컬 브랜치 `codex/project-workbench`. 기반 원격 SHA `07055c747b56a0d7e8a9181927cb8d446ec70694`에서 독립 복제해 작업했다. 최초 기록 시 원격 업로드와 Pages 배포는 수행하지 않았다.

## 구현과 검사

- `npm run validate`: 기존 콘텐츠 규칙과 작업실 스키마 통과.
- `npm run test:workbench`: 9개 통과. 순환/미등록 의존관계, 선행 작업, 근거/다른 검토자, 만료된 배정, 취소, 시도 한도, proposal-only, 버전 충돌·쓰기 잠금·실패 시 원본 보존, 읽기 검수 인자와 결과 계약, 실제 CLI의 프로젝트 등록·사건 중복 방지를 확인.
- `npm run test:context`: 기존 17개 통과. 1,205편 합성 자료의 기존 내보내기 계약을 포함한다. 실제 사이트의 사용량·AI 성능 평가와 다르다.
- WSL Ubuntu의 Ruby 3.2 / Jekyll 4.4.1로 실제 사이트 빌드 성공. 기존 index.html pagination 경고가 있으나 빌드는 성공했다. HTML fixture를 Jekyll 빌드라고 부르지 않았다.
- 렌더된 `feed.xml`을 XML로 파싱하고 `/workbench/state.json`을 JSON으로 확인.
- 기존 exporter를 렌더된 `_site`에 실행: 공개 글 19개, 부록 1개. 운영 작업실은 글 색인에 섞이지 않는다. 로컬 내보내기의 기반 SHA 표시는 원격 게시의 증거가 아니다.
- `node scripts/workbench-agent-review.mjs plan --task agent-review`: 두 역할·읽기 전용·소스 fingerprint·시간 한도를 확인. 실제 모델 계정에 접속한 run은 수행하지 않았다.

## 실제 브라우저

Jekyll 출력물을 loopback HTTP로 제공해 PC와 390×844 모바일에서 확인했다.

- 작업 보드 ↔ 연결 흐름 ↔ 참고 저장소 전환과 선택 상태.
- 작업의 완료 조건·선행 작업·근거 상세 표시.
- 인수인계 복사 완료 표시와 실제 JSON 다운로드.
- 참고 저장소의 문서 검토/사용 상태·미고정 버전 구분.
- Home의 Hanasaka·네 영역·기존 프로젝트 카드와 새 작업실 링크.
- 모바일에서 가로 넘침 없음. 참고 SHA도 화면 안에서 줄바꿈.

다운로드 확인에서 브라우저 도구 응답이 지연됐다. 파일 생성과 후속 Home 이동은 확인했으며 이 지연을 앱 실행 성능 수치로 사용하지 않는다.

## 관찰한 실패와 수정

최초 파일 교체 검사는 Windows 도구의 제한된 TEMP에서 EPERM이 발생했다. 복제본 안의 전용 `_workbench_test_tmp`로 옮겨 원자적 교체와 충돌 검사를 통과했다. 저장 실패 때 원본을 지우는 우회는 추가하지 않았다.

고정 미리보기 포트의 bind가 거부되어 OS가 배정한 임시 로컬 포트로 검수했다. Windows 보안 설정은 변경하지 않았다. 실제 Jekyll 확인을 위해 WSL에 Ruby/Jekyll 개발 도구를 설치했다.

## 남은 범위

실제 두 모델의 동시 실행·계정 접근·모델 품질·프로세스 타임아웃은 별도 실측이 필요하다. 인자/결과 계약 검사를 그 실측으로 보고하지 않는다. 에이전트의 무인 수정·상시 이벤트 실행·자동 병합·자동 게시 운영은 아직 제공하지 않는다.
