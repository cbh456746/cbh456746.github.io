[Mesh Avatar Studio](https://github.com/shinshin86/mesh-avatar-studio)를 기반으로 한 장의 캐릭터 일러스트를 움직이는 **2D 메쉬 아바타**로 제작하고 있다. 눈·입 표정, 고개와 상체 움직임, 머리카락 물리를 추가하고 일반 사용자용 실행 앱까지 만들었다. Cubism 모델을 생성하거나 VTube Studio의 모델 목록에 설치하는 방식은 아니다.

**이번 개발 프로젝트의 저장소는 현재 비공개이며, 품질 검증과 공개 준비를 마친 뒤 공개할 예정이다.**

## 지금까지 만든 것

제작 흐름은 **일러스트 → 표정 그림과 숨은 영역 복원 → 독립 파츠 분리 → 관절·물리 설정 → 자세 검토 → 실행 앱**이다.

- 얼굴·목·몸통·팔·머리카락·모자·옷깃을 **14개 독립 파츠**로 구성했다. AI가 만든 소재도 원본과 합성 결과를 비교하며 보완했다.
- 별도 실기 시험에서 **iPhone → VTube Studio → 로컬 앱**으로 고개·눈·입 추적값이 전달되는 것을 확인했다.
- **Windows portable 앱**을 제작했다. Node.js·Python을 별도로 설치하지 않고 실행하며, 감도 저장·재연결·트레이 실행·OBS용 투명 출력 페이지를 제공한다.

14.9초·30fps 영상에서 고개 기울임, 머리카락 흔들림, 좌우 눈 감기와 입 움직임을 볼 수 있다. 공개본은 오디오와 원본 메타데이터를 제거했다. 실제 얼굴이나 추적 수치가 함께 나오지 않으므로, 이 영상만으로 추적 지연·음성 동기화·OBS 1080p/60fps 송출을 검증했다고 볼 수는 없다.

## 겪었던 문제와 대응

| 문제 | 적용한 해결 방법 |
| --- | --- |
| 머리카락을 움직이면 옷과 주변 그림도 함께 움직임 | 단순 잘라내기에서 독립 RGBA 소재로 전환하고 가려진 몸통·어깨를 복원했다. |
| 움직인 파츠와 원래 그림이 겹쳐 두 개처럼 보임 | 밑그림에 남은 중복 영역을 정리하고 파츠별 그림의 소유 영역을 구분했다. |
| 목과 팔이 늘어나거나 어깨 연결이 어긋남 | 부모·자식 연결과 회전 중심을 적용하고 어깨 위치를 보정했다. 옷깃은 몸통에 연결했다. |
| 터미널 실행과 방송 페이지별 연결 관리가 번거로움 | 더블클릭 앱이 추적을 한 번 관리하고, 출력 페이지가 같은 값을 받도록 구성했다. |

이 대응으로 큰 중복·동반 이동·관절 늘어짐을 줄였지만, 모든 자세의 시각 품질이 완성된 것은 아니다.

## 이번 검토에서 남은 과제

- **머리카락 형태 복원:** 원본보다 귀 뒤·어깨 위가 많이 비어 있다. 옆머리와 뒷머리의 볼륨을 먼저 복원해야 한다.
- **눈·입의 연속성:** 약 9.87초에 열린 눈과 감긴 눈이 겹친다. 입도 타원형 크기 변화에 치우쳐 있으며, 현재 실시간 입력에서는 둥근 입용 그림을 선택하지 못한다.
- **접합과 회전:** 턱 아래 각진 경계를 보완하고, 평면 기울임을 넘어 방향에 따른 얼굴·상체 형태와 가림 관계를 설계해야 한다. 머리카락 내부 가닥의 반응도 세분화할 계획이다.

다음 순서는 **원본 형태 복원 → 눈·입 전환 → 목 접합 → 회전 자세 → 머리카락 물리 → 실제 방송 검증**이다. 파일·좌표 검사가 통과해도 자연스러운 그림이 보장되지는 않으므로, 원본 비교와 전환 프레임 심사를 강화한다.

원본 일러스트·분리 소재·실행파일·인증 정보·개인 작업 경로는 이 글에 포함하지 않았다. 현재 공개하는 것은 개발 기록과 시연용 영상이다.

## 후속 연구 기록 · 2026년 10월 18일

위 소개와 영상은 초기 버전의 기록이다. 이후의 방향별 형태·시선·연결 실험, 남은 한계와 물리 OFF 상태의 입체감 검증 계획은 [Live2D와 비교한 아바타 제작 연구](/research/vtuber-avatar-live2d-gap/)에 정리했다. 후속 후보도 목표 시각 품질과 실제 방송 검증을 모두 통과한 상태는 아니다.


## 현재 개발 방향과 Board · 2026년 11월 5일

**[Mesh Avatar Board에서 목표·작업·근거와 다음 단계를 확인할 수 있다.](/workbench/?project=mesh-avatar)** 이 소개글의 초기 앱, 이후 회전 연구와 별도 후보를 같은 완성본으로 묶지 않고 기록했다.

| 구분 | 확인한 결과 | 남은 한계 |
| --- | --- | --- |
| 초기 Mesh Avatar 앱 | 독립 파츠·Windows 실행 앱·iPhone→VTube Studio 입력 연결과 공개 시연을 만들었다. | 실행·연결 성공이 모든 자세의 자연스러움이나 실제 방송 품질 승인을 뜻하지 않는다. |
| Silver Braid 회전 연구 | [Hiyori와 비교한 연구](/research/hiyori-silver-braid-head-motion-study/)에서 볼·턱·목의 국소 변형과 제한적인 방향 표현을 분리해 진단했다. | Hiyori의 선택 사진만으로 실제 회전각·깜박임 속도·물리 지연을 추정할 수 없다. |
| Rose Duet 01 후보 | 별도 입체 두상·깊이 가림과 독립적인 시선·표정 구조를 시험했다. 10월 27일 보관 기록에 새 검사 13개, 정적 24자세, 합성 입력 480프레임 검토가 남아 있다. | Hiyori급 작화는 미달이다. 위를 볼 때의 턱밑·원통형 목, 측면 머리카락과 세부 표정이 부족하며 새 후보의 VTS 입력 어댑터·실제 OBS 검증도 남아 있다. |

위 수치는 **이번 문서 정리에서 과거 검사 기록을 재확인한 것**이다. 오늘 같은 실험을 다시 수행했거나, 합성 입력으로 실제 얼굴 추적과 방송까지 검증했다는 뜻이 아니다. 새 후보의 원화·소재·내부 보고서는 이 공개 글에 추가하지 않았다.

다음 개발 순서는 **고개·목·시선의 동일 입력 비교 → 소재 소유 영역과 숨은 부위 재검수 → 두상·턱·목 연결 → 표정·상체·머리카락의 복합 동작 → 실제 추적·방송 → 제작 흐름과 실행 앱 정리**다. 각 단계는 파일·수치 검사와 실제 확대 이미지·연속 동작 심사를 함께 통과해야 한다.

[LivLiv Player 사용 기록](/notes/livliv-player-getting-started/)도 참고 자료로 연결했다. 공개된 파츠 구조와 회전 키폼은 비교할 가치가 있지만, 현재 자체 엔진에 도입하거나 품질 개선 효과를 입증한 상태는 아니다. [원본 저장소](https://github.com/livliv-dev/player)의 재생기와 이미지에서 모델을 만드는 서비스, 코드와 샘플 캐릭터의 이용 조건을 구분해 검토한다.


## 제작 흐름과 동작 검수의 재검토 · 2026년 11월 6일

컨셉에서 상반신 메인을 만든 뒤 그 그림을 고정하고, 보이는 원본을 추출하며 숨은 영역·새 표정만 생성하는 흐름으로 정면 외형을 개선했다. 새 후보는 23개 레이어와 45개 제어를 구성하고 LivLiv Player 0.3.0 재생기를 고정 도입했다. 위 11월 5일의 미도입 설명은 당시의 상태다.

후속 사용 검토에서는 상체 과이동, 얼굴 회전 중 이목구비 변형, 약한 머리카락 반응과 부족한 가슴·옷의 추종이 지적됐다. 화면 변화와 파일 검수만으로 자연스러운 회전·관절·물리를 승인할 수 없었다. [새 연구 글](/research/avatar-workflow-art-and-motion-review/)에서 이전·현재 워크플로우, 현재 코드와 합성 입력 진단, 다음 합격 기준을 비교했다. 이번 글 작성에서 리깅을 고쳤거나 새 실제 VTS·OBS 방송을 검증한 것은 아니다. 새 캐릭터 소재와 개발 저장소는 비공개로 유지한다.
