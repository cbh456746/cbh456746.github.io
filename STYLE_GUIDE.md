# Style guide

## Write for a person reading the page

- Start with what the reader can do or understand after reading. Use a useful title and a one-sentence `subtitle`.
- Write Korean primarily. Explain an unfamiliar abbreviation on first use and retain source language only where it helps.
- Give each paragraph one point. Put the action or answer before background detail, and use `##` then `###` headings so a reader can scan the page.
- Prefer a short sequence for tasks, a compact table for real comparisons, and copyable commands for procedures. Keep caveats next to the step they affect. Remove repeated introductions, padded summaries and lists that merely rephrase the paragraph above.
- Read the rendered page on a desktop and narrow mobile screen. Check whether someone unfamiliar with the topic can find the first step, the expected result and the next action without decoding a wall of text.

## Use media when it earns its place

- A screenshot should point out a control, state or result; a diagram should explain a relationship; a short video or animation should show motion that a still image cannot. Place it beside the relevant explanation and give it a factual caption.
- **There is no image or video quota.** A clear text-only page is better than decorative or repeated media. Do not add media merely to make a page look busy.
- Describe the useful content in alt text, not the filename. Make moving media optional or controllable, avoid forced autoplay, and account for loading cost and small screens.
- Before publishing, verify source, reuse rights, attribution, public scope, hidden personal details and image metadata. Check that the media actually loads and that a reader still understands the step if it does not.

Do not put passwords, private keys, personal phone numbers or unreviewed personal data into the repository.
