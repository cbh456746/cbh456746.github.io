일러스트 한 장을 넣고 얼굴 추적을 연결하면 자연스러운 버튜버 아바타가 완성될까? 지금까지 뚜껑형 PNGTuber, 방향별 이미지를 전환하는 아바타, 파츠를 분리해 움직이는 메시 아바타를 제작하며 이 질문을 실험했다.

실행파일과 얼굴 추적 연결은 만들 수 있었다. 그러나 **원래 캐릭터의 그림을 유지하면서, 고개를 어느 방향으로 움직이고 어디에서 멈추더라도 자연스럽게 보이는 것**은 훨씬 어려웠다. 이 글은 만들어진 기능과 남은 문제를 구분하고, Live2D Cubism 기반 아바타의 제작 원리와 비교해 다음 개발 방향을 정리한다.

> **현재 판정 · 2026년 10월 18일**
>
> 이미지 전환형 앱은 소스 공개와 로컬 실행파일 검증을 진행했다. Mesh Avatar 실험은 방향별 형태와 연결을 일부 개선했지만, 목표로 삼은 Akari 수준의 시각 품질에 도달했다고 판정하지 않았다. 다음 기준은 **물리 OFF 상태에서 자연스러운 회전 자세를 먼저 확보하고, 이후 표정과 물리를 결합하는 것**이다.

여기서 Akari는 비교 대상으로 관찰한 VTube Studio 기본 모델을 뜻한다. 모든 Live2D 모델의 품질을 대표하는 절대 기준이나, 이 프로젝트와의 제휴를 의미하지 않는다. 아래의 제작 방향과 합격 기준은 이 프로젝트의 제안이며, 공식 제품의 보장 사항과 구분한다.

## 1. 궁극적으로 만들고 싶은 것

사용자는 캐릭터 일러스트와 프로젝트 저장소 링크를 AI 에이전트에 전달한다. 에이전트는 필요한 그림을 준비하고, 움직임을 설계하고, 결과를 검수한 뒤 방송용 실행파일을 만든다. 사용자는 복잡한 개발 명령을 익히지 않고 캐릭터와 입력 장치를 선택해 방송 화면에 올린다.

이 목표에는 네 가지 조건이 함께 들어 있다.

| 조건 | 실제로 충족해야 하는 것 |
| --- | --- |
| 캐릭터 보존 | 얼굴 비율, 선화, 눈과 장식의 디자인이 자세마다 달라지지 않는다. |
| 자연스러운 움직임 | 회전·시선·깜박임·발화·부속물의 흔들림이 결합해도 형태가 유지된다. |
| 제작의 재현성 | 다른 에이전트와 다른 캐릭터에서도 같은 절차와 검수 기준을 적용할 수 있다. |
| 방송 사용성 | 실행·추적·설정 복원·OBS 출력이 일반 사용자에게 이해하기 쉬워야 한다. |

현재는 각 조건의 일부를 확보한 상태다. **어떤 일러스트라도 완성도 높은 아바타로 자동 변환하는 범용 시스템은 아직 완성되지 않았다.**

최종 목표의 중심은 눈에 보이는 품질과 제작의 재현성이다. 특정 파일 확장자를 만들었다는 사실만으로 이 목표를 달성할 수는 없다. 동시에 기존 방송 도구에서 모델을 직접 불러오는 호환성이 필요하다면, 그것은 별도의 기술 목표로 명확히 다뤄야 한다.

## 2. 지금까지의 세 가지 접근

세 작업은 문제를 다르게 나누어 해결한 실험이다. 뒤의 프로젝트가 앞의 프로젝트를 완전히 대체한 것은 아니며, 개발 시기와 검증 범위도 서로 다르다.

### 2.1 뚜껑형 PNGTuber: 음성에 반응하는 최소 구조

첫 접근은 R.E.P.O. 캐릭터의 뚜껑처럼 열리는 움직임에서 아이디어를 얻은 PNGTuber였다. 기본적인 말하기 반응과 눈 깜박임을 명확한 이미지 상태로 표현했다.

한 방향에 입 닫힘·중간·열림 세 상태와 눈 뜸·감음 두 상태를 만들고, 좌우 개폐 방향을 합쳐 캐릭터당 12개 상태를 구성했다. 마이크 음량을 기준으로 상태를 고르고, 오래된 입력이 남아 입이 계속 열리는 상황을 줄이기 위해 입력 갱신과 무효화도 다뤘다.

이 방식은 단순한 연출을 분명하게 제어하기 좋았다. 반면 자연스러운 얼굴 회전이나 눈의 원근, 머리카락의 독립적인 움직임을 표현하는 데 필요한 정보는 제한적이었다. [뚜껑형 PNGTuber 프로젝트 소개](/projects/repo-style-pngtuber/)

### 2.2 이미지 전환형: 방향과 표정의 수를 늘리기

다음 접근은 좌우 5단계와 상하 5단계를 조합한 25방향에, 눈 뜸·감음과 입 닫힘·중간·열림을 결합한 6상태를 준비하는 것이었다. 총 150개의 이미지 중 현재 입력에 맞는 한 장을 표시한다.

여기서 ‘6표정’은 정확히는 **눈과 입의 여섯 상태 조합**이다. 기쁨·슬픔·분노처럼 독립적인 감정 여섯 종류를 제작했다는 뜻은 아니다.

Illustration Avatar Studio에서는 이를 Windows 앱으로 구성했다. 설정 화면과 별도의 방송 창을 제공하고, 수동 미리보기·마이크·VTube Studio 얼굴 추적을 연결했다. 앱 자체가 이미지를 생성하는 것은 아니며, 제작 단계에서 에이전트가 사용할 수 있는 이미지 생성 도구가 필요하다. [프로젝트 소개](/projects/browser-vtuber-avatar-project/) · [공개 소스](https://github.com/cbh456746/browser-vtuber-avatar)

### 2.3 Mesh Avatar: 같은 그림을 연속적으로 변형하기

Mesh Avatar Studio 기반 실험에서는 이미지에 삼각형 구조인 **메시(mesh)**를 붙이고, 정점의 위치를 바꾸어 그림을 변형했다. 얼굴·목·귀·눈·머리카락·의상·장식을 분리하고, 각 부위가 어떻게 연결되고 가려지는지 설계하는 방향이다.

초기에는 파츠 분리와 연결, 이후에는 시선과 머리의 독립, 부위별 변형, 방향별 기준 그림과 좌표 등록까지 진행했다. 이를 통해 정면 그림 전체를 함께 휘는 방식의 한계를 줄이려 했다. [Mesh Avatar 프로젝트 소개](/projects/mesh-avatar-studio/)

| 접근 | 확보하기 쉬웠던 것 | 주된 한계 |
| --- | --- | --- |
| 뚜껑형 PNGTuber | 명확한 말하기 상태, 가벼운 제어 | 얼굴 회전과 세밀한 표현 범위 |
| 이미지 전환형 | 자세마다 직접 그린 모습을 표시 | 상태 사이의 외형 일치와 전환의 연속성 |
| 메시 아바타 | 같은 소재를 쓰는 연속 변형과 부위별 제어 | 방향별 형태·가림·접합부의 제작 품질 |

## 3. Live2D 아바타와 무엇이 다른가

### 3.1 Live2D Cubism과 VTube Studio의 역할

이 글에서 Live2D 기반 제작은 그림을 분리하고 변형·표정·물리를 설계하는 Cubism의 제작 방식을 뜻한다. **리깅(rigging)**은 이런 움직임과 제어 관계를 모델에 설정하는 작업이다.

VTube Studio는 모델을 구동하는 방송 환경이며, 외부 프로그램이 인증을 거쳐 추적 파라미터를 읽을 수 있는 Public API도 제공한다. 현재 두 자체 앱은 이 API에서 입력값을 받아 각자의 방식으로 아바타를 그린다. API 연결이 성공했다는 사실은 Cubism 모델을 제작했다는 뜻이 아니다. [VTube Studio 공식 API](https://github.com/DenchiSoft/VTubeStudio#readme)

현재 자체 아바타를 VTube Studio의 모델 목록에 넣는 `.moc3` 기반 모델로 내보내는 기능은 검증되지 않았다. 자체 렌더러의 품질 개선과 Cubism 형식 호환은 별도 과제로 유지한다.

### 3.2 Live2D의 형태는 미리 설계되어 있다

Cubism의 파라미터는 고개 방향이나 입 개방처럼 제어할 동작을 나타낸다. 특정 값에 저장한 대표 형태를 **키폼(keyform)**이라고 하며, 중간 값에서는 형태를 보간한다. 키폼은 새 완성 PNG 한 장과 같은 개념이 아니다. [공식 파라미터 설명](https://docs.live2d.com/en/cubism-editor-manual/parameter/)

얼굴 회전에서는 눈·코·입·귀·외곽을 부위별로 조절해 가까운 쪽과 먼 쪽의 관계를 만든다. 공식 튜토리얼 역시 개별 변형기와 원근을 다루고, 대각선 생성 후 어색한 움직임을 수정하도록 안내한다. [공식 얼굴 XY 제작](https://docs.live2d.com/en/cubism-editor-tutorials/xy/)

눈동자가 눈 바깥으로 나오지 않게 가리는 클리핑 마스크처럼, 무엇을 어디까지 보여 줄지도 모델의 일부다. [공식 클리핑 마스크 설명](https://docs.live2d.com/en/cubism-editor-manual/clipping-mask/)

### 3.3 비교의 기준은 엔진 이름보다 완성된 모델의 동작이다

| 항목 | Cubism에서 설계하는 방식 | 현재 이미지 전환형 | 현재 메시 실험 |
| --- | --- | --- | --- |
| 그림 구성 | 분리 소재와 움직일 때 드러날 영역 준비 | 자세·눈·입별 완성 이미지 | 독립 파츠와 일부 숨은 영역 복원 |
| 고개 회전 | 부위별 원근·키폼·대각선 보정 | 25개 방향 중 선택 | 부위별 변형과 좌우 기준점 적용 |
| 시선·눈 감기 | 눈 내부 이동과 눈꺼풀·마스크 설계 | 눈 뜸·감음 이미지 선택 | 독립 시선과 눈꺼풀 구조를 실험 |
| 입·표정 | 개방과 형태 등 필요한 제어를 설계 | 닫힘·중간·열림의 세 단계 | 별도 입 리그와 회전 결합 보정 필요 |
| 부속물 | 제작한 흔들림 형태를 물리 출력으로 구동 | 프레임에 그려진 모습에 의존 | 귀걸이·머리카락 물리와 부착 관계 실험 |
| 품질 결정 요인 | 소재·리깅·조정·검수의 완성도 | 모든 상태 그림과 전환의 일치성 | 형태 데이터·가림·접합·복합 동작의 완성도 |

표의 Cubism 항목은 가능한 제작 방식을 요약한 것이다. 모든 Live2D 모델이 동일한 파라미터, 가동 범위, 품질을 갖는다는 의미는 아니다. 비교할 때는 특정 모델의 실제 움직임과 출력 조건을 맞춰야 한다.

## 4. 실제로 확보한 성과

### 4.1 실행과 방송 준비의 부담을 줄였다

터미널에서 서버를 실행하던 방식에서, 더블클릭으로 설정과 방송 창을 여는 방향으로 발전했다. 이미지 전환형 앱에서는 완성된 캐릭터팩을 선택하고, OBS에서 방송 창을 캡처하는 절차를 준비했다.

소스 공개, 로컬 실행파일 제작, 일반 사용자용 정식 바이너리 배포는 서로 다르다. 2026년 10월 18일의 이미지 전환형 프로젝트는 공개 소스와 로컬 검증용 실행파일 단계이며 정식 다운로드 Release를 제공하는 상태는 아니다.

### 4.2 얼굴 추적 연결의 실제 문제를 수정했다

VTube Studio의 플러그인 승인 창이 반복되고 얼굴 추적이 이어지지 않는 문제가 있었다. 인증 응답 처리와 재접속 시 토큰 재사용을 수정했고, 실제 VTS 연결 및 얼굴 추적값 변화까지 제한된 실기 시험으로 확인했다.

이 과정에서 **API 인증 성공, 얼굴 감지, 입력값 수신, 캐릭터 표시, 실제 방송 송출**을 별도의 확인 항목으로 나누었다. 하나가 성공했다고 나머지까지 완료로 판단하면 문제 위치를 찾기 어렵다. 구체적인 범위는 [공개 검증 기록](https://github.com/cbh456746/browser-vtuber-avatar/blob/main/docs/VALIDATION.md)에 남겼다.

### 4.3 그림 자체의 오류를 제작 규칙으로 되돌렸다

말하지 않을 때 입이 사라지는 문제는 닫힌 입 이미지에서 입선이 빠진 사례였다. 입력 감도를 조절하는 것으로 해결할 문제가 아니었다. 해당 그림을 보정하고 이후 제작에서는 닫힌 입 상태를 실제 표시 크기와 밝고 어두운 배경에서 확인하도록 했다.

고개 좌우·상하 입력을 0.85배로 줄이는 기본값도 반영했다. 다만 최종 그림 선택은 다섯 단계로 나뉘므로, 눈에 보이는 이동량이 모든 순간 연속적으로 15% 줄어드는 것은 아니다.

헤일로의 배경 제거와 고해상도·동작 간 일관성도 제작 피드백으로 기록했다. 이 피드백을 문서에 반영한 작업과 기존 모든 그림을 실제로 수정한 작업은 구분한다. [아트 제작 기준](https://github.com/cbh456746/browser-vtuber-avatar/blob/main/docs/ART_DIRECTION.md)

### 4.4 메시 실험에서 원인을 더 구체적으로 분리했다

다음은 Mesh Avatar의 주요 실험 단계다. 개별 후보의 자동 검사 결과를 최종 시각 품질로 해석하지 않는다.

| 실험 | 수행한 일 | 남긴 판단 |
| --- | --- | --- |
| 기본 파츠·연결 실험 | 독립 소재, 부모·자식 연결, 목·어깨·장식 보정 | 단순 크롭만으로 움직일 소재가 완성되지 않음 |
| lab-01 | 홍채·흰자·눈꺼풀과 시선 제어 분리 | 시선과 머리 회전을 구분할 기반 확보 |
| lab-02 | 부위별 3×3 제어 형태, 연결점과 국소 표정 변형 | 형태가 깊이 수식에 의존해 회전의 설득력이 부족 |
| lab-03 | 좌우 참고 그림, 57개 기준점, 눈·귀·목 분리, 숨은 소재 보완 | 좌우는 부분 개선, 상하·대각선·모자·앞머리와 경계는 미완성 |

## 5. 반복해서 만난 실패와 그 원인

### 5.1 서로 잘 그려진 이미지도 같은 캐릭터의 연속 장면이 아닐 수 있다

방향마다 이미지를 생성하면 개별 그림은 보기 좋아도 눈의 비율, 앞머리 갈래, 장식 무늬, 목 길이가 조금씩 달라질 수 있다. 이를 빠르게 바꾸면 외형이 흔들린다.

원하는 것은 각 장의 독립적인 완성도와 장면 사이의 일치성을 함께 갖추는 것이다. 정면 원본을 고정하고, 비대칭 장식을 보존하며, 회전 외의 시선·표정·조명·몸 자세를 통제할 필요가 있다.

### 5.2 부드러운 변형이 자연스러운 회전을 보장하지 않았다

정면 그림을 연속적으로 압축하고 이동시키면 끊김은 줄일 수 있다. 그러나 코·볼·턱·귀가 동일한 비율로 움직이면 얼굴이 입체적으로 돌아가기보다 평면이 휘는 것처럼 보인다.

가동 범위를 줄이는 보수 조치는 결함의 노출을 낮췄지만, 새로운 방향의 형태를 완성한 것은 아니었다. 자연스러운 작은 동작을 보존하되 충분히 다른 방향의 자세도 따로 제작해야 했다.

### 5.3 파츠 분리에서 그림의 소유 관계가 깨졌다

머리카락 파츠에 귀의 선이 남아 있고 별도의 귀 파츠도 움직이면 귀가 두 개처럼 나타난다. 눈꼬리 선이 얼굴 피부와 눈꺼풀에 나뉘어 남으면 눈을 감을 때 선이 끊어지거나 돌출될 수 있다.

**어떤 선과 색을 어느 파츠가 소유하는지**를 명확히 해야 한다. 이미지가 정상적으로 열리고 투명 채널이 존재하는지만 검사해서는 이런 오류를 발견할 수 없다.

가려진 부분을 복원하는 작업도 필요하다. 공식 소재 분리 안내 역시 잘라낸 뒤 움직임에서 드러날 부분을 추가로 그리는 과정을 설명한다. [공식 소재 분리 안내](https://docs.live2d.com/en/cubism-editor-manual/divide-the-material/)

### 5.4 연결점이 맞아도 주변 그림은 어색했다

귀걸이의 부착점 좌표가 일치해도 고리의 방향과 귀의 외곽이 맞지 않으면 떨어져 보인다. 턱의 이동을 목의 관절로 그대로 사용하면 목이 과도하게 늘어날 수 있다.

따라서 부착점 외에 주변 경계 곡선, 겹침 영역, 회전 중심, 가림 순서를 함께 검수해야 했다. lab-03에서는 턱 표면과 목의 기준을 분리해 과도한 추종을 줄였다.

### 5.5 파일 해상도와 실제 세부 묘사는 달랐다

이미지 전환형 시험에서는 한 장의 생성 시트에 여러 자세를 담고 나누는 과정을 사용했다. 작은 셀을 큰 출력 파일로 저장해도 원래 선화의 세부 정보가 같은 비율로 늘어나지는 않는다.

다음 제작에서는 핵심 방향을 고해상도 개별 이미지로 준비하고, 비교표는 검수용으로 만든다. 최종 방송 크기의 선명도와 확대했을 때의 경계를 함께 확인해야 한다.

### 5.6 수치 검사와 시각 판정이 섞였다

파일 보존, 연결점 오차, 삼각형 뒤집힘 검사는 필요하다. 하지만 눈이 지나치게 좁아지거나 머리카락이 평평해져도 이 검사를 통과할 수 있다.

실제로 메시 수를 크게 늘린 실험에서도 회전 품질은 충분히 좋아지지 않았다. 뒤집히지 않은 삼각형이 심하게 압축되는 경우도 있었다. 이후에는 **구조가 정상인지, 그림이 올바른지, 움직임이 자연스러운지**를 나누어 판정하는 방향으로 바뀌었다.

## 6. 가장 큰 벽: 입체감과 물리

### 6.1 입체감은 자세에 따른 형태와 가림의 문제다

이 프로젝트에서 입체감은 회전할 때 얼굴의 부피와 부위 간 관계가 설득력 있게 유지되는 것을 뜻한다. 고개를 돌리면 가까운 눈과 먼 눈의 폭이 달라지고, 코와 입의 위치가 턱·귀와 다른 관계로 바뀐다. 고개를 숙이면 모자 윗면과 앞머리의 겹침도 달라져야 한다.

현재 가장 부족한 것은 이런 **방향별 목표 형태와 그 사이의 변화**다. 좌우 기준점만 추가하는 단계에서 더 나아가, 상하·대각선의 윤곽과 모자·머리카락의 부피를 제작해야 한다.

### 6.2 물리는 시간에 따른 반응의 문제다

Cubism의 물리는 입력 파라미터를 진자 모델에 연결하고, 계산한 흔들림을 출력 파라미터에 적용한다. 반응 속도, 흔들림의 크기, 수렴 등을 조정할 수 있다. 이 출력이 구동할 머리카락이나 의상의 형태는 모델에 준비되어 있어야 한다. [공식 물리 설명](https://docs.live2d.com/en/cubism-editor-manual/physics-operation/) · [공식 물리 설정 절차](https://docs.live2d.com/en/cubism-editor-manual/physical-operation-setting/)

이 프로젝트에서 구현해야 할 것은 머리를 움직였다가 멈췄을 때 귀걸이와 머리카락이 적절히 뒤따르고, 부착부를 유지하며 안정되는 반응이다. 파츠를 통째로 흔드는 것 외에 길이를 따라 굽는 형태, 움직일 수 있는 범위, 주변 파츠와 겹치는 방식을 함께 설계해야 한다.

### 6.3 먼저 분리해서 검증해야 하는 이유

물리와 표정까지 한꺼번에 켜면 어떤 변형이 문제를 일으켰는지 찾기 어렵다. 따라서 첫 단계에서는 흔들림을 끄고 고개 회전만 확인한다.

**물리 OFF는 파츠를 화면에 고정한다는 뜻이 아니다.** 모자와 귀, 머리카락 뿌리와 귀걸이 부착부는 머리를 정상적으로 따라가야 한다. 추가적인 관성·반동만 멈춘 상태에서 연결과 입체감을 검수한다.

> 다음 성공 기준은 “메시가 더 정교해졌다”가 아니라, **“정지한 회전 자세도 자연스럽고, 움직이면 부속물이 설득력 있게 따라온다”**이다.

| 한 장에 없는 정보 | 옆얼굴·귀 뒤·가려진 머리카락은 추정과 제작이 필요하다. 생성 결과를 원본의 확정된 모습처럼 취급하지 않는다. |

| 실시간 성능 | 오프라인 영상의 재생 fps와 실제 앱의 처리 속도는 다르다. 목표 장치에서 추적·렌더·캡처를 함께 측정해야 한다. |
| 파일 형식 호환 | 자체 렌더링과 Cubism 모델 내보내기를 구분한다. 검증된 내보내기 경로 없이 VTS 네이티브 모델 지원을 주장하지 않는다. |
| 범용 자동화 | 특정 캐릭터를 위한 보정이 다른 얼굴·체형에도 적용되는지 아직 충분히 검증하지 못했다. |

보조적인 3D 구조를 활용하는 방법은 다음 실험 후보다. 얼굴·코·귀·모자에 깊이를 주어 회전 위치의 초안을 계산하고, 그림체에 맞게 2D 형태를 보정하는 방식이다. Cubism에도 추정 3D 변형으로 키폼 제작을 돕는 기능이 있다. [공식 3D 회전 표현 보조 기능](https://docs.live2d.com/en/cubism-editor-manual/apply-3d-rotation-expression/)

이 사실이 현재 프로젝트의 보조 3D 구조가 완성됐다는 뜻은 아니다. 앞선 공통 깊이 수식의 한계를 반복하지 않으려면 얼굴·눈·코·귀·머리카락을 각각 평가하고, 원화의 표현에 맞는 보정과 가림을 남겨야 한다.

## 8. 다음 제작 과정과 통과 기준

아래는 앞으로 적용할 개발 계획이다. 기존 실험에서 일부 기반을 만들었지만, 이 표 전체가 통과된 상태는 아니다.

### 8.1 원본과 움직임의 범위를 먼저 고정한다

원본 일러스트와 안정 버전을 보존하고 새 후보를 별도로 만든다. 최초 범위는 머리·모자·머리카락·귀·목으로 제한한다. 몸과 어깨의 이미 좋은 동작을 동시에 바꾸면 개선 여부를 비교하기 어렵다.

좌우와 상하의 허용 범위를 정하고, 시선·입·표정·몸 자세·조명을 고정한다. 생성 요청에 적힌 각도를 실제 추적 장치의 보정된 물리 각도처럼 보고하지 않는다.

### 8.2 다섯 방향에서 시작해 아홉 방향으로 확장한다

정면, 좌우 회전, 고개 들기와 숙이기를 먼저 제작한다. 이 다섯 방향의 외형이 맞으면 대각선 네 방향을 추가한다. 아래 표의 좌우는 화면 기준이며, 실제 구현에서는 좌표의 부호와 반전 규칙을 별도로 기록한다.

| 상하 / 좌우 | 화면 왼쪽 | 정면 방향 | 화면 오른쪽 |
| --- | --- | --- | --- |
| 고개 들기 | 왼쪽 위 | 위 | 오른쪽 위 |
| 중립 높이 | 왼쪽 | 정면 | 오른쪽 |
| 고개 숙이기 | 왼쪽 아래 | 아래 | 오른쪽 아래 |

각 방향은 같은 캐릭터의 설계 자료다. 실제 재생 프레임으로 곧바로 교체하지 않는다. 비대칭 모자나 귀걸이를 단순 좌우 반전으로 처리하지 않으며, 생성 결과가 원본과 다르면 형태 데이터로 옮기기 전에 수정한다.

### 8.3 기준 그림을 실제 모델의 형태로 옮긴다

부위의 기준점에 더해 얼굴 외곽, 눈꺼풀 곡선, 모자와 머리카락의 실루엣을 맞춘다. 먼 귀가 가려지는 정도와 턱 아래 피부처럼 방향에 따라 달라지는 노출 영역도 함께 설계한다.

같은 파츠의 중간 형태를 계산할 때 정점과 텍스처 좌표의 대응을 유지한다. 파츠별 변형은 독립적으로 조정하되, 서로 연결되는 부위는 같은 부착 기준을 공유하게 한다.

### 8.4 중간 자세를 검토하고 실패 구간을 고친다

첫 검토 자료는 9방향 기준표, 실제 모델의 좌우 5단계×상하 5단계 비교표, 느린 회전 영상, 자유롭게 멈출 수 있는 미리보기로 구성한다.

**25개 비교 이미지는 렌더링 검사 지점이며 25장의 새 원화를 생성한다는 뜻이 아니다.** 정지 검사를 통과해도 중간 변화가 갑작스러울 수 있으므로 왕복·대각선·원형 이동과 임의 정지를 함께 검사한다. 가림 경계와 변형이 큰 구간은 더 촘촘하게 살핀다.

문제가 생기면 입력 위치를 저장하고 같은 자세를 재현한다. 해당 구간에 보정 형태나 가림 수정을 추가하고, 주변 자세와 이미 통과한 자세도 다시 확인한다. 모든 부위에 영향을 주는 수식을 반복 조절하는 대신 수정 범위를 좁히는 것이 목표다.

### 8.5 표정, 물리, 방송 환경을 순서대로 결합한다

| 단계 | 추가할 것 | 다음 단계로 넘어갈 조건 |
| --- | --- | --- |
| 정적 회전 | 방향별 형태와 가림 | 검토 범위에서 캐릭터·부피·연결 유지 |
| 표정 결합 | 독립 시선, 반감김·완전 감김, 입 개방 | 회전 중 눈·입·턱의 위치와 선화 유지 |
| 단일 물리 | 귀걸이 하나, 머리카락 한 묶음 | 부착부 고정, 설득력 있는 굽힘·반동·수렴 |
| 복합 물리 | 앞머리·땋은 머리·필요한 의상 반응 | 움직임끼리 충돌하거나 접합부가 벌어지지 않음 |
| 실사용 | 실제 추적과 Windows 앱·OBS | 입력 지연·부하·재연결·추적 손실·녹화 확인 |

이 순서의 목적은 물리를 늦추는 것 자체가 아니라, 원인을 분리하고 수정 효과를 정확하게 판정하는 데 있다.

## 9. 수정해야 할 프로그램 구조

### 9.1 제작 단계와 실행 단계를 나눈다

제작 도구는 원본 분석, 필요한 그림 생성, 소재 분리, 좌표 등록, 형태 설계와 검수를 담당한다. 실행기는 검수된 모델을 불러와 입력에 맞게 안정적으로 표시한다.

```text
제작: 원본 고정 → 필요한 소재 복원 → 방향별 형태 제작
      → 파츠·연결·가림 등록 → 복합 동작 검수 → 모델 패키지

실행: 추적·음성 입력 → 입력 보정 → 자세·표정·물리 평가
      → 가림과 합성 → 방송 화면
```

위 흐름은 제안하는 책임 분리다. 현재 두 프로젝트의 코드를 그대로 합치면 완성되는 구조라는 뜻은 아니다.

### 9.2 캐릭터 전용 값을 수정 가능한 모델 데이터로 옮긴다

입 중심 좌표, 귀걸이 부착점, 머리카락 뿌리처럼 캐릭터마다 다른 값을 엔진 코드에 직접 넣으면 새 캐릭터마다 프로그램을 고쳐야 한다.

모델 데이터에는 다음 정보를 함께 담는 방향을 제안한다.

- **그림 정보:** 원본 기준, 파츠 ID, 해상도, 좌표계, 투명 경계, 파일 버전.
- **형태 정보:** 방향별 대표 형태, 곡선, 보정 형태, 허용 가동 범위.
- **연결 정보:** 부모·자식 관계, 부착점, 겹침 영역, 목·귀·머리카락의 경계.
- **표시 정보:** 마스크, 앞뒤 순서, 방향에 따른 노출과 가림.
- **동작 정보:** 시선·표정·물리 입력, 우선순위, 반응과 제한.
- **검수 정보:** 어떤 입력과 출력에서 통과했고 무엇이 남았는지.

### 9.3 형태·시간 반응·합성을 구분한다

| 담당 영역 | 책임 | 실패를 찾는 방법 |
| --- | --- | --- |
| 형태 계산 | 현재 고개·눈·입 값에서 각 파츠가 어떤 모양인지 계산 | 물리를 끄고 같은 입력의 정지 렌더 비교 |
| 물리 계산 | 이전 움직임에 따른 관성·반동·수렴 계산 | 같은 입력 궤적을 반복하고 정지 후 반응 확인 |
| 합성 | 마스크와 그리기 순서로 보이는 영역 결정 | 파츠별 보기와 밝고 어두운 배경에서 경계 확인 |

새 구조에서는 이 관계를 명시적으로 관리해야 한다. 같은 입력과 초기 상태를 다시 넣었을 때 같은 결과를 재현할 수 있어야 수정 전후를 비교할 수 있다.

입력에서는 ‘측정값 0’, ‘입력 없음’, ‘오래된 값’을 구분하고, 누가 입이나 눈의 최종 값을 결정하는지도 명확히 해야 한다. 그래야 음성·표정·얼굴 추적이 동시에 같은 상태를 덮어쓰는 문제를 줄일 수 있다.

## 10. 품질을 어떻게 판정할 것인가

### 10.1 서로 다른 검사를 하나의 PASS로 합치지 않는다

| 검사 | 확인하는 것 | 이것만으로 알 수 없는 것 |
| --- | --- | --- |
| 파일·해시·규격 | 입력 보존, 파일 누락, 등록 정보의 재현성 | 그림이 예쁘고 자연스러운지 |
| 기하·연결 | 잘못된 숫자, 뒤집힘, 선택한 부착점 이탈 | 눈·턱·모자의 부피와 선화 품질 |
| 정지 자세 | 특정 입력에서 외형·가림·연결 | 중간 움직임의 갑작스러운 변화 |
| 연속 동작 | 왕복·복합 입력에서의 시간적 일관성 | 모든 장치의 실시간 성능 |
| 실기 방송 | 실제 입력·앱·캡처·녹화의 동작 | 다른 PC와 모든 캐릭터에서의 동일한 결과 |

Mesh lab-03 기록에는 81개 복합 자세의 기하 검사와 12초 오프라인 렌더가 남아 있다. 단위 검사와 일부 브라우저 검사는 통과했지만, 전체 E2E에는 12개 실패가 남았고 실제 VTS·OBS 종합 검증도 별도였다. 이 후보를 완성된 방송 모델로 승격하지 않은 이유다.

### 10.2 시각 검수는 독자가 이해할 수 있는 질문으로 한다

- 중립에서 원본의 인상과 선이 유지되는가?
- 눈만 움직일 때 턱과 머리 외곽이 함께 끌려가지 않는가?
- 고개 회전에서는 가까운 눈·먼 눈·코·귀의 관계가 실제로 달라지는가?
- 들거나 숙일 때 모자·앞머리·턱 아래의 부피가 설득력 있는가?
- 귀·머리카락·피부에 중복 윤곽이나 투명한 구멍이 생기지 않는가?
- 회전한 채 눈을 감고 말해도 눈꼬리와 입이 얼굴에 붙어 있는가?
- 고개를 멈췄을 때 부속물이 과도하게 늘어나거나 계속 진동하지 않는가?

‘어디에서 멈춰도 자연스럽다’는 지향점은 **정의한 허용 범위 안에서** 검증한다. 무한한 모든 자세를 시험했다거나 모든 입력의 미적 품질을 수학적으로 증명했다고 표현하지 않는다. 실패 구간과 검수하지 못한 조건도 함께 기록한다.

### 10.3 성능은 실제 방송 환경에서 확인한다

30fps로 인코딩한 영상은 재생 파일의 속도를 나타낸다. 실제 추적과 렌더링이 30fps로 동작했다는 증거가 아니다. 소프트웨어 렌더러의 측정치 역시 실제 GPU와 OBS의 성능을 대신할 수 없다.

추후에는 프레임 처리 시간, 입력에서 표시까지의 지연, 부하 시 끊김, 연결 재시도, 추적 중단과 복구를 실제 실행파일에서 측정해야 한다. 품질과 성능을 동일한 모델 버전으로 검사해야 한다.

## 11. 재사용 가능한 제작 시스템으로 확장하기

첫 목표는 **한 캐릭터의 머리에서 자연스러운 회전과 복합 표정을 완성하는 것**이다. 다음 목표는 같은 절차로 두 번째 캐릭터를 제작하는 것이다. 첫 번째가 시각 품질을 검증한다면, 두 번째는 제작 과정의 재사용성을 검증한다.

장기적으로는 눈·입·머리카락·액세서리를 교체할 수 있는 모듈을 지향한다. PNG 파일만 교환하는 방식으로는 충분하지 않다. 연결 위치, 곡선과 겹침, 가림, 움직임의 범위, 호환 조건까지 함께 있어야 한다.

초기에는 같은 그림체와 체형 안에서 호환되는 모듈부터 다루는 편이 적절하다. 목 굵기, 얼굴 비율, 선 두께, 조명이 크게 다른 파츠를 모두 자동 결합할 수 있다고 약속하지 않는다. 직접 호환되는 조합, 추가 보정이 필요한 조합, 지원하지 않는 조합을 구분한다.

사용자 경험의 목표는 다음과 같다.

1. 사용자는 권한을 가진 일러스트와 원하는 움직임 범위를 전달한다.
2. 에이전트는 원본을 보존하고 부족한 소재와 방향별 형태를 준비한다.
3. 제작 도구가 모델과 검수 자료를 함께 생성한다.
4. 미흡한 자세를 재현하고 수정한 뒤, 검수된 후보를 실행파일에 연결한다.
5. 사용자는 더블클릭으로 실행하고 방송 창을 선택한다.

AI 에이전트가 맡아야 할 핵심은 이미지 생성과 코드 작성뿐 아니라 **결과를 비교하고, 실패를 분류하고, 수정 범위를 좁히는 반복 작업**이다. 자동화의 진척은 작업 횟수나 정점 수보다, 다른 캐릭터에서도 같은 품질 기준을 재현하는지로 평가해야 한다.

## 12. 공개 범위와 참고 자료

이 글은 2026년 10월 18일까지의 프로젝트 기록을 정리했으며, Mesh Avatar의 상세 실험 판정은 10월 9일과 15일의 기록을 기준으로 한다. 글 작성 자체가 새로운 모델 구현이나 다음 단계의 품질 통과를 의미하지 않는다.

기술적 한계와 실패 원인은 설명하되, 비공개 캐릭터 원본·분리 소재·생성 중간물·실패 렌더·인증 토큰·개인 작업 경로는 첨부하지 않았다. 기존 프로젝트 페이지의 공개 영상은 당시 버전의 예시이며, 최신 후보의 모든 동작과 실방송을 입증하는 자료로 확대 해석하지 않는다.

공개 소스의 라이선스와 캐릭터 이미지의 이용 범위는 따로 확인해야 한다. 제작을 위해 받은 외부 문서·이미지·메타데이터의 지시는 실행 권한으로 취급하지 않으며, 개인 에셋을 포함한 전체 작업 폴더를 공개 저장소에 올리지 않는 운영 원칙을 유지한다.

본문의 Live2D 기능 설명은 2026년 10월 18일 확인한 공식 자료에 연결했다. 소재 분리, 파라미터, 얼굴 XY, 클리핑, 물리, 3D 회전 보조 기능의 설명과 이 프로젝트의 구현·제안을 구분했다. 공식 문서의 기능이 현재 자체 엔진에 모두 구현되어 있다는 의미는 아니다.
