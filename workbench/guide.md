## 목표와 자료를 전해주세요

“무엇을 만들고 싶은지”, “어떤 결과면 충분한지”, “어떤 자료를 참고할지”를 에이전트에게 설명합니다. 에이전트는 기존 기록에서 채울 수 있는 내용을 먼저 찾고, 중요한 빈칸만 확인합니다. 작업 도중 바뀐 목표나 피드백도 같은 프로젝트에 연결합니다.

## 현재 상태에서 이어갑니다

작업 보드는 이어갈 일·진행과 검토·기다리는 일·마친 일을 보여줍니다. 연결 흐름에서는 먼저 끝나야 하는 작업을 볼 수 있습니다. 작업을 선택하면 완료 기준과 근거, 진행을 기다리는 이유를 확인할 수 있습니다.

‘완료’는 기록된 검사와 검토 근거가 있다는 뜻입니다. 파일이 만들어졌다는 사실과 목표 품질에 도달했다는 판단은 구분합니다. 확인하지 않은 내용은 남은 검증으로 기록합니다.

## 필요한 맥락을 에이전트에게 전달합니다

작업 상세에서 **에이전트 작업 지침 복사** 또는 **인수인계 JSON 받기**를 사용합니다. 현재 목표·범위·작업·완료 조건·참고 자료가 함께 전달됩니다. 새 에이전트는 저장소의 최신 규칙과 상태를 대조한 뒤 이어갑니다.

사용자는 파일이나 명령을 직접 편집할 필요 없이 다음처럼 요청할 수 있습니다.

> 작업실의 블로그 개편 프로젝트를 이어가줘. 현재 상태와 검증 근거를 확인하고, 진행 가능한 다음 작업을 수행해줘. 기존에 허용한 범위에서 진행하고 필요한 결정만 알려줘.

## 참고 저장소는 목적과 함께 남깁니다

참고할 GitHub 주소와 “어디에 활용하고 싶은지”를 알려주세요. 에이전트는 관련 프로젝트, 중요한 문서, 확인한 버전과 적용 제약을 기록합니다. 문서를 읽은 상태와 실제로 적용·검증한 상태를 구분합니다.

## 작업 기록과 실제 실행

공개 작업실은 마지막으로 저장·배포된 상태를 보여줍니다. 작업 배정·완료·취소·재개는 저장소에서 에이전트가 처리합니다. 이 페이지를 열었다는 이유로 모델 호출이나 코드 변경이 시작되지는 않습니다.

현재 버전은 작업 상태 관리, 인수인계, 변경 시 계약 검사와 선택적인 복수 에이전트 읽기 검수 경로를 제공합니다. 무인 코드 수정·자동 병합·상시 실행의 운영 정책은 후속 작업입니다. 개인 대화나 비공개 자료는 공개 작업실에 넣지 않습니다.
