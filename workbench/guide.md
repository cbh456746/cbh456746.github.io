[Board로 돌아가기]({{ '/workbench/' | relative_url }})

Board는 **공개 프로젝트의 현재 상태를 읽는 곳**입니다. 아래 순서대로 따라가면 처음 보는 작업도 약 3분 안에 맥락을 파악할 수 있습니다.

![프로젝트 선택, 작업과 근거 확인, 인수인계 및 개인 기록 보관으로 이어지는 세 단계]({{ '/assets/images/workbench/workbench-flow.svg' | relative_url }})

## 1. 프로젝트와 다음 일을 찾기 {#project}

[Board]({{ '/workbench/' | relative_url }}) 상단의 **프로젝트** 메뉴에서 대상을 고릅니다. 요약 카드의 목표·완료한 작업 수·진행 가능한 작업 수·다음 단계·기록 갱신일을 읽습니다. 이 숫자는 마지막 배포 시점의 공개 기록입니다.

새 목표나 참고 자료를 등록하려면 에이전트에게 “무엇을 만들지, 어떤 결과면 충분한지, 무엇을 참고할지”를 전하세요. 에이전트가 기존 기록과 연결하고 중요한 빈칸만 확인합니다. 공개 범위에 넣을 문구와 자료는 게시 전에 검수합니다.

## 2. 세 가지 보기로 맥락 확인하기 {#views}

| 보기 | 언제 쓰나요? | 무엇을 확인하나요? |
| --- | --- | --- |
| **작업 보드** | 현재 할 일을 찾을 때 | 이어갈 일, 진행·검토 중인 일, 보류·완료 상태 |
| **연결 흐름** | 무엇을 먼저 해야 하는지 볼 때 | 선행 작업과 다음 단계의 관계 |
| **참고 저장소** | 다른 프로젝트나 도구를 참고할 때 | 참고 목적, 확인 버전, 적용 제약과 검증 수준 |

작업 카드를 선택하면 오른쪽(작은 화면에서는 아래)에 **설명 → 완료 기준 → 선행 작업 → 근거**가 나옵니다. “완료”는 해당 근거가 기록됐다는 뜻입니다. 목표한 품질까지 달성했는지, 실사용 시험이 남았는지는 근거 내용을 따로 읽어야 합니다.

## 3. 다음 에이전트에게 이어주기 {#handoff}

선택한 작업에서 **에이전트 작업 지침 복사** 또는 **인수인계 JSON 받기**를 누릅니다. 두 결과에는 현재 목표·범위·완료 기준·참고 자료·기록 버전이 들어갑니다. 새 에이전트는 저장소의 최신 규칙과 실제 상태를 대조한 뒤 이어갑니다.

> Board의 블로그 개편 프로젝트를 이어가줘. 현재 상태와 검증 근거를 확인하고, 진행 가능한 다음 작업을 수행해줘. 기존에 허용한 범위에서 진행하고 필요한 결정만 알려줘.

이 문장은 **요청 예시**입니다. 페이지를 보는 것만으로 AI가 실행되거나 코드가 바뀌지는 않습니다.

## 4. 사진과 영상으로 작업 보여주기 {#media}

프로젝트에 공개 가능한 사진이나 영상을 등록하면 요약 아래의 **프로젝트 미디어** 카드에 표시됩니다. 이미지는 대체 텍스트, 영상은 표지 이미지와 재생 조작을 제공합니다. 현재 블로그 Home 사진과 기존 방송 아바타 프로젝트 영상은 표시 방식의 예시이며, 후자는 Board 조작 안내 영상이 아닙니다.

운영 에이전트에게 미디어 원본·출처·사용 범위·설명 문구를 주면 공개에 적합한 파일만 선별하고 메타데이터와 링크를 검수합니다. 개인 사진·대화 캡처·비공개 시연은 공개 Board에 넣지 않습니다. 미디어가 없는 프로젝트에는 갤러리가 나타나지 않습니다.

## 5. AI 대화 전문과 프롬프트 보관하기 {#conversation}

[대화·프롬프트 기록 도구]({{ '/workbench/records/' | relative_url }})는 별도의 **개인 파일 작성 화면**입니다.

1. **대화 제목**과 프로젝트 이름을 적습니다.
2. **턴 추가**로 사용자·AI·도구·시스템 발화를 순서대로 기록합니다. 한 턴의 줄바꿈과 전문은 그대로 보존됩니다.
3. 다시 쓰고 싶은 사용자 턴에서 **프롬프트로 보관**을 누르거나 새 프롬프트를 직접 추가합니다. 프롬프트에는 원래 턴의 ID가 남습니다.
4. **JSON 저장**으로 파일을 내려받고 실제 저장 여부를 확인합니다. 다음에는 **JSON 불러오기**로 같은 파일을 엽니다.

브라우저에서 편집하는 동안 서버 업로드·자동 저장·계정 동기화는 없습니다. 탭을 닫거나 새로고침하기 전에 JSON을 저장해야 합니다. 저장 파일은 **개인 비공개 기록실**에 보관하고, 나중에 AI가 분석해야 할 때 해당 파일을 직접 첨부하거나 권한을 준 비공개 저장소에서 읽도록 요청하세요. 공개 블로그 저장소·작업 상태 JSON·공개 인수인계 패킷에는 대화 전문을 넣지 않습니다. 공용 PC에서 사용하지 마세요.

개인 기록실은 이 공개 블로그와 **별도의 Private 저장소**로 운영합니다. Board에는 그 저장소의 주소나 원문이 없고, 이 페이지에서 비공개 기록에 접속하는 기능도 없습니다. AI가 나중에 기록을 읽으려면 사용자의 새 요청과 실제로 허용된 접근이 필요합니다. JSON은 암호화된 파일이 아니므로 다운로드 폴더의 사본도 관리하세요. [공개·비공개 기록 경계와 AI 사용 원칙](https://github.com/cbh456746/cbh456746.github.io/blob/main/docs/BOARD_PRIVATE_RECORDS.md)을 참고하세요.

## 실제 운영 상태 {#limits}

Board는 마지막으로 저장·배포된 공개 스냅샷입니다. 작업 배정·완료·취소·재개는 저장소에서 에이전트가 처리합니다. 현재는 상태 관리, 인수인계, 계약 검사와 선택적인 읽기 검수 경로가 있습니다. 무인 코드 수정·자동 병합·상시 실행은 후속 운영 과제입니다.
